# Fuzzing mod-host's protocol

libFuzzer harnesses (clang, AddressSanitizer, UndefinedBehaviorSanitizer) for the part of mod-host
that reads bytes from a controller. They link the protocol sources only, so they need no JACK server
and no plugins. `fuzz/socket_fuzz.c` stands in for `src/socket.c`: its `socket_send()` copies each reply into
a buffer that the harness reads, so a run opens no socket. The shipped library does not contain it.

| harness | what it feeds |
| --- | --- |
| `fuzz_protocol` | `protocol_parse()` over a table with every pattern shape (words, `%` wildcards, `...`) |
| `fuzz_dispatch` | the whole dispatcher (`host_dispatch_register*`) over a backend that answers every error code |
| `fuzz_scenario` | `host_scenario_load()`, the scenario file reader, with `$NAME` substitution |
| `fuzz_statepaths` | `MakePluginStatePath()` and `GetPluginStateDir()` below a scratch directory |

```
apt-get install -y clang      # plus libclang-rt-<N>-dev where the distribution packages it apart
make fuzz                     # build/fuzz/fuzz_*
make fuzz-run FUZZ_TIME=60    # each harness for 60 s over a scratch copy of its corpus
make fuzz-corpus              # regenerate fuzz/corpus from tests/host-scenarios.txt and fuzz/gen-corpus.sh
```

One harness by hand: `build/fuzz/fuzz_dispatch fuzz/corpus/dispatch` (add `-max_total_time=60`).
A crash leaves its input in `build/fuzz/artifacts/`; run the harness on that file to reproduce it.

The seed corpora in `fuzz/corpus/` are generated by `fuzz/gen-corpus.sh` from the scenario file and a
list of verbs and malformed shapes. `fuzz_dispatch` takes a salt byte first (which error code the
backend answers), then the command.
